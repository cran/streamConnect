Getting Started with streamConnect

Michael Hahsler

streamConnect connects data stream sources and stream mining algorithms through sockets or web services. It works with the DSD (data stream) and DSC (data stream clustering) interfaces from the stream package.

This guide shows two common workflows: reading a stream over a socket and updating a remote clusterer through a web service. For more control over the web service endpoints and deployment, see the help pages for publish_DSD_via_WebService() and publish_DSC_via_WebService().

Install and load

Install the released package from CRAN:

install.packages("streamConnect")

Load the package and select an available local port for the examples:

library(streamConnect)
#> Loading required package: stream

We will use the same free server port throughout this vignette. Some systems do not allow the use of local ports, then the code in this vignette will not be executed.

run_code <- TRUE
tryCatch({
  port <- httpuv::randomPort()

  }, warning = function(w) {
    message("Ports unavailable: ", w)
    run_code <<- FALSE
  }, error = function(e) {
    message("Ports unavailable: ", e)
    run_code <<- FALSE
})

Read a data stream over a socket

Start a background process that publishes a stream. The publisher opens a socket server and writes data in blocks. Since the socket format does not include column names, provide them when creating the reader.

socket_process <- publish_DSD_via_Socket(
  DSD_Gaussians(k = 3, d = 2),
  port = port
)
socket_process
#> PROCESS 'R', running, pid 43094.

Connect a local DSD reader and request points from the stream:

socket_dsd <- DSD_ReadSocket(
  port = port,
  col.names = c("x", "y", ".class")
)

points <- get_points(socket_dsd, n = 10)
head(points)
#>           x         y .class
#> 1 0.6800171 0.8880206      1
#> 2 0.2142635 0.1373371      2
#> 3 0.3880251 0.7212369      3
#> 4 0.6784146 0.9536051      1
#> 5 0.5979322 0.9152445      1
#> 6 0.4995153 0.7062725      3

Close the reader and stop the publisher when finished:

close_stream(socket_dsd)
if (socket_process$is_alive()) socket_process$kill()
#> [1] TRUE

Update a remote clusterer via a web service

Web services also support request and response operations. Start a clusterer in a background process, then create a local DSC interface for it:

clusterer_process <- publish_DSC_via_WebService(
  "DSC_DBSTREAM(r = .05)",
  port = port
)

clusterer <- DSC_WebService(paste0("http://127.0.0.1:", port))
clusterer
#> Web Service Data Stream Clusterer: DBSTREAM
#> Served from: http://127.0.0.1:34986 
#> Class: DSC_WebService, DSC_R, DSC 
#> Number of micro-clusters: 0 
#> Number of macro-clusters: 0

Send a batch of points to the remote clusterer and retrieve its centers and weights through the local interface:

stream <- DSD_Gaussians(k = 3, d = 2, noise = 0.05)
update(clusterer, stream, n = 500)

Publish a stream through a web service

To expose a data source over HTTP, publish a DSD and read it with DSD_ReadWebService(). The service returns CSV by default; JSON and RDS serialization are also available through the serializer argument.

source_process <- publish_DSD_via_WebService(
  "DSD_Gaussians(k = 3, d = 2)",
  port = port
)

remote_stream <- DSD_ReadWebService(paste0("http://127.0.0.1:", port))
get_points(remote_stream, n = 10)
#> # A tibble: 10 × 3

Next steps

  • Use publish_DSD_via_Socket() and DSD_ReadSocket() for continuous point-to-point stream transfer.
  • Use publish_DSD_via_WebService() and DSD_ReadWebService() to serve stream data over HTTP.
  • Use publish_DSC_via_WebService() and DSC_WebService() to update and inspect a remote clusterer.
  • Set serve = FALSE to write a plumber task file for deployment with a hosting environment of your choice.

See the package reference for the full function documentation.
